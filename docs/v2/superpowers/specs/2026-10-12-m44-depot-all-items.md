# M44：仓库识别覆盖全部页签 + 道具图展示

- 里程碑：M44
- 分支：`m44-depot-all-items`（从 `refactor/v2` 新建）
- 状态：待实现
- 上游：M27 仓库识别（`DepotInfo` 回调 + 整表替换）、M43 资源代理（`account/assets.py`，本次复用它加 `kind=item`）

## 1. 来源与目标

用户 2026-10-12 原话：

> 仓库识别任务中，需要对仓库的所有道具都识别，包括合成玉，源石，抽卡券等等，然后在仓库数据展示时，需要带有道具的图片

同轮两项裁决（用户选择）：

1. **识别范围**：扫全部页签再合并入库（不是只改展示，也不是先只调研）；
2. **抽卡券来源**：与道具一起在各自页签里扫，不额外做顶部资源栏 OCR。

## 2. 事实基础（2026-10-12 本机实测，模拟器 2560×1440 + 已连内核）

### 2.1 MAA 的仓库识别只看一个页签

`resource/lib/maa/Darwin/resource/tasks/tasks.json` 里与仓库有关的任务只有 8 个，其中页签动作只有两个：

| 任务 | 动作 | 说明 |
| --- | --- | --- |
| `DepotBegin` | `JustReturn` | `next` 是候选列表：`[Depot, DepotMaterialTab, DepotAllTab, DepotMaterialTabClicked, …]` |
| `Depot` | `DoNothing`（`sub: [Depot-Entry]`） | `next: [DepotMaterialTab]` |
| `DepotMaterialTab` | `ClickSelf`，`roi [945, 0, 300, 138]` | **实际链走的是这个：点「养成材料」页签** |
| `DepotAllTab` | `ClickSelf`，`roi [450, 0, 300, 138]` | 另一个页签位置，内置链没用它 |

`DepotMatchData` / `DepotBaseRect` / `DepotQuantity` 是识别器的参数任务（网格坐标与数量阈值），说明识别本身由内核 C++ 的 Depot 分析器做，**页签由任务链决定**。

### 2.2 一次真机识别（15:52:40 提交 `Depot`）实际拿到什么

26 件：21 件养成材料 + 5 件基础道具（龙门币 / 至纯源石 / 合成玉 / 赤金 / 采购凭证），其中材料是 `2001/2002/2003/3301/3302/3303` 与 `mod_*`、`31xxx` 系列。

**缺的**：寻访凭证 `7003`、十连寻访凭证 `7004`、高级凭证 `4004`、资质凭证 `4005`、家具零件 `3401`、源石碎片 `3141`，以及消耗品/凭证/家具页签里的全部东西——它们不在「养成材料」页签里。

### 2.3 两个必须一起修的问题

1. **整表替换会吃掉数据（实测事故）**：识别前库里 77 行，这一轮只识别到 26 件，`DepotService.replace_all` 直接**整表替换**，77 行变成 26 行。M42 给森空岛同步做过「数量级不对整轮不写」的护栏（`SKLAND_MIN_CHARS`），仓库这条**一直没有**。M44 必须补上同样的下限护栏。
2. **顶部资源栏的数值被截掉后三位**：主界面顶部实测 `4797534 / 242920 / 475`，而识别入库的是 `4797000 / 242000 / 475` —— 即后三位被截断/取整。页面上把这种近似值当精确值展示是假事实，要么标注「约」，要么另想办法（见 §3.2 不做）。

### 2.4 道具图可用

`https://web.hycdn.cn/arknights/game/assets/item/{icon}.png` 实测 **200 / 33 KB PNG**（`icon` 取自本机 `resource/maa-layers/repo/resource/item_index.json` 的 `icon` 字段，如 `3003.png`）。同域名的干员资源已有防盗链（浏览器直连 403），所以道具图**同样走后端代理**。

`item_index.json`：479 条，字段 `name` / `icon` / `classifyType`（`NONE 212 / MATERIAL 95 / NORMAL 95 / CONSUME 71 / MEMENTO 6`）/ `rarity` / `sortId` / `usage` / `description` —— 名字与图标文件名本地就有，缺的只是页面上那张图。

## 3. 范围

### 3.1 本里程碑做

1. **W0 真机取证**（§2，已完成；页签栏的**实际位置与全部页签名**要在 W1 里再截图确认一次）。
2. **扫全部页签**：在我们自己的资源层里加一条链，依次点开每个页签并各识别一次；识别结果**按页签合并**入库，不再无脑整表替换。
3. **下限护栏**：一轮识别的条目数低于阈值（默认按上次数量的比例 + 绝对下限，具体值 W1 定稿）就**整轮不写**，并把原因记进识别记录。
4. **道具图代理**：`GET /api/account/assets/item/{icon}`（复用 M43 的 `GameAssetService`，`ASSET_KINDS` 加 `item` → 上游 `item/{icon}`），前端仓库页显示图标。
5. **仓库页展示**：每个道具一行/一卡显示图标 + 名字 + 数量 + 分类；名字/图标优先取本机 `item_index.json`（服务端补全），缺条目时如实显示 id 与占位图。
6. **数量近似值的标注**：顶部资源栏那几项（龙门币/合成玉/至纯源石）在页面上标「约」（后三位被截断是上游行为，见 §2.3-2）。
7. **测试与文档**：页签链的解析/合并语义单测、护栏单测、资源代理 `item` 类型、前端图标与「约」标注用例；docs/04/05/09/13/12 同步。

### 3.2 本里程碑不做

- **不做顶部资源栏 OCR**（用户裁决）：合成玉/至纯源石/龙门币继续用识别值，只标注「约」；
- **不改内核**：页签链通过 `resource/maa-layers/` 的资源覆盖层加，内核升级不冲突；
- **不做仓库道具的编辑/导入导出**（M27 的老口径不变）；
- **不做家具/皮肤仓库**（那是另一套界面，M44 只覆盖仓库页签）。

## 4. 设计

### 4.1 页签链（W1 真机定稿）

两个候选，靠真机实验二选一：

- **候选 A（首选）：让内置链直接扫「全部」页签。** 在我们层里覆盖 `DepotMaterialTab`（内置链必点的那一步）为「点『全部』页签」，这样一个 `Depot` 任务就能拿到全部道具，合并语义都不用改。前提：仓库里确实有「全部」页签、且它列出所有分类的道具 —— `DepotAllTab` 这个任务的存在说明 MAA 认为至少有第二个页签，roi `[450, 0, 300, 138]` 就是它的位置猜测。
- **候选 B（保底）：多页签多轮识别 + 合并。** 用自定义链依次点开每个页签，每个页签后跑一次识别；服务层改成「按页签合并」。代价是要认页签身份（内核的 `DepotInfo` 不带页签信息），实现更绕，但能覆盖任何界面结构。

W1 的真机步骤：进仓库 → 截图看页签栏 → 分别点每个页签截图 → 记录 roi 与页签名 → 跑 `Depot` 看 `DepotInfo` 的 id 集合 → 决定 A 还是 B。

### 4.2 合并与护栏（服务层）

- `DepotService.replace_all` 增加 `min_items` 语义：`len(items) < min_items` 时**整轮不写**，记一条 warning 与识别记录的 `skipped_reason`（照 M42 `SKLAND_MIN_CHARS` 的做法）；
- 阈值来源：配置项 `account.depot_min_items`（默认 20，可关）——比「上次数量的百分比」简单且可解释；
- 候选 B 落地时：合并粒度改为「按页签替换」，需要链上把页签身份传给回调（内核回调不带，只能由我们自己的链在每次识别前写一个标记），这部分设计在 W1 结论出来后再定稿。

### 4.3 资源代理（复用 M43）

- `ASSET_KINDS["item"] = "item"`，URL 就是 `{ASSET_BASE_URL}/item/{icon}`；
- `icon` 白名单沿用现有正则（`3003.png`、`mod_unlock_token.png` 这类都落在 `[A-Za-z0-9_\[\]().\-]` 内）；
- 缓存目录 `resource/assets-cache/item/`，一周 `Cache-Control`，命中不打上游。

### 4.4 前端

- 仓库页每个道具：图标（本机代理取 blob，同 M43） + 名字 + `× 数量` + 分类；
- 图标缺失（`item_index` 里没有这个 id）→ 占位图，名字显示 id；
- 顶部资源栏类条目（龙门币/合成玉/至纯源石）数量前加「约」并 `title` 说明「上游识别只给到千位」；
- 保持既有筛选（分类下拉、搜索）与分页。

## 5. 兼容与风险

| 风险 | 处理 |
| --- | --- |
| 页签链改动后识别结果仍是部分页签 | 用**下限护栏**兜住：条目数异常就整轮不写，不会再把 77 行覆盖成 26 行 |
| 覆盖内核任务名的兼容性 | 资源层是增量层，只覆盖我们明确要改的节点；记录在 docs/13，内核升级后要复核一次 |
| 顶部数值近似 | 页面标「约」，不假装精确 |
| 道具图缺失 | 占位图 + 显示 id，不留破图 |
| 真机验证依赖模拟器与游戏状态 | W1/W3 各需要一轮真机；用户需保证游戏可被 MAA 操作 |

## 7. 验收

1. 真机：一轮仓库识别后，库里能同时看到养成材料、基础道具、消耗品与凭证页签的道具（含寻访凭证/十连寻访凭证）；
2. 护栏：构造一次只有 3 件的识别，表**不被覆盖**，识别记录里能看到跳过原因；
3. 展示：仓库页每件道具都有图标（走 `/api/account/assets/item/...`，命中缓存不重复打上游），顶部资源栏数值带「约」；
4. 门禁：后端全量（只有既有真资源失败）+ 前端 typecheck/test/build + `dump_openapi --check` + `gen:api:check` + 两个 smoke + 文案基线；
5. `--no-ff` 合并回 `refactor/v2` 并打 `v2-m44`。
