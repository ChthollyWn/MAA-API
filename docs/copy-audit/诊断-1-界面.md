## 一、结论

**整体水平中等偏上，但问题不是"AI 味"，是"工程师写给自己看"。**

经典 AI 腔在本项目几乎不存在：整份界面清单里 `抱歉`/`感谢`/`谢谢` **0 条**，emoji 装饰 **0 条**（全库仅 `scripts/probe_sqlmodel_alembic.py` 的 ✅⚠️❌），感叹号 **0 条**，`——` 当冒号 **0 条**，「不是…而是…」**0 条**，粗体强调在界面里 **0 条**（`ai-tells.md` 那 142 条集中在后端 docstring）。所以**不需要"去 AI 味"运动**。

真正拉低观感的是三类：把**开发笔记**写进用户要读的字段说明；把**接口/字段/源码**当成解释工具；同一件事**多个叫法**。改写方向是"从实现口径改成用户口径"，不是"删形容词"。

## 二、逐类病灶

### 2.1 开发笔记／实现细节泄漏（最重）

**判据**：文案里出现「内核默认值」「源码」「docstring」「字段」这类只对维护者有意义的词；或出现"我为什么这么写"的自指。

- `maa_api/domain/task.py:255` 是否自动启动客户端；内核默认值 False（即不自动启动，源码 StartUpTask.cpp 的 params.get("start_game_enabled", false)）。需要自动启动客户端时请显式设为 True
- `maa_api/domain/task.py:230` 判别联合 discriminator，固定为 StartUp；由任务类型选择器决定，用户不需要填写（同类 10 处：`:282 :322 :473 :657 :782 :844 :911 :1259 :1323`）
- `maa_api/domain/task.py:568` …旧文案「默认 True」与源码相反（官方文档的 @default true 与源码冲突，以源码为准）
- `maa_api/domain/task.py:539` …该设置只在真正执行招募时用得上——内核在 times=0 时主循环不执行，旧文案「仅在 times 为 0 时生效」与源码相反
- `maa_api/domain/task.py:558` 加急次数；仅在 expedite 为 True 时有效。内核 v6.17.5 已不再使用该值（RecruitTask.cpp 取到后以 [[maybe_unused]] 丢弃…），本字段仅为兼容旧提交保留，因此没有默认值
- `maa_api/domain/task.py:378` …该参数自内核 v6.8.0 起已弃用，内核改用 medicine_expire_days（理智药过期天数，非 0 即视为 2 天）；本服务的字段仅为兼容旧提交保留
- `maa_api/domain/task.py:1291` …内核对该键没做缺省判空（ReclamationCraftTaskPlugin 直接取 find(...).value()），所以必须显式下发——这也是它需要默认值的原因
- `maa_api/domain/task.py:685` …默认值（全部七个设施，按标准换班顺序）由本服务约定，内核没有默认值。设施名选项包括 "Mfg", "Trade"…
- `maa_api/domain/task.py:950` 开局分队名；留空 = 内核自动选择（内核源码取空串，而不是官方文档写的「指挥分队」）
- `maa_api/domain/task.py:941` 模式；…（170 字，含 6 个模式分支、括号套括号）

**改法**：`label` 保持名词短语；`description` 只写两件事——**这个参数影响游戏里会发生什么**、**不填会怎样**。给用户看的默认值写「默认开启／关闭」，不写「内核默认值 True（启用）」。内核版本差异、源码行为、与官方文档冲突的考证，全部移到 `docs/` 或代码注释；用户只需要知道"现在填什么有效"。170 字的模式说明拆成 `label` + 选项名（选项名已经写了「刷分/奖励点数」「刷源石锭」），正文压到 40 字内。

### 2.2 错误提示无信息量／漏英文与 JSON

**判据**：前缀只是复述「失败了」，正文给不出下一步；或者兜底路径把非中文内容直接抛给用户。

- `web/src/features/tasks/queue/QueueView.tsx:108`（同 `:118`、`:131`）操作失败：${errorMessage(error)}
- `web/src/api/errors.ts:68` `Request failed with status ${status}`；`:83` `The API request failed`；`:91`/`:95` `The network request failed`
- `web/src/realtime/client.ts:148`（同 `:520`）`Authentication failed`；`:284` `Unable to create WebSocket connection`；`:381` `WebSocket origin is not trusted`；`:415` `WebSocket send failed`
- `web/src/routes/logs/index.tsx:146` 连接错误：{realtime.error} ← 上一行的英文串就显示在这里
- `web/src/features/updates/types.ts:294` `return JSON.stringify(value)` ← 兜底时用户会看到一坨原始 JSON
- `web/src/features/tasks/form/errors.ts:13` 请求被策略拒绝（403）。若操作本应允许，请检查代理是否剥离了 X-Token 鉴权头，并重新登录。
- `web/src/routes/login.tsx:68` 服务拒绝了已保存 token 的认证请求（403）。token 仍保留，请输入正确的访问 token 后重试。
- `web/src/features/updates/use-updates.ts:44` 更新请求已提交，但接口没有返回记录编号。
- `web/src/features/tasks/history/PipelineDetail.tsx:51` 服务端没有返回任务明细。
- `web/src/features/agent/AgentPage.tsx:431`（同 `:467`）Agent 对话失败。

**改法**：`errorMessage()` 必须在最外层做一次本地化映射，`api/errors.ts` 的三个英文兜底改成中文；`realtime/client.ts` 的 `error` 字段改成稳定 code（`auth_failed` 等），文案在展示层映射。用户级错误允许保留 HTTP 状态码，但**排在句中**、且同一屏最多一个。禁止把 `JSON.stringify` 结果当文案。

### 2.7 标点与排版

- 区间三种写法：`1 ~ 65535`（`web/src/features/settings/channel-config.ts:273`）、`范围 ${minimum} ~ ${maximum}`（`web/src/features/settings/schema.ts:110`、`web/src/features/tasks/editor/ScalarControls.tsx:112`）、`2–48 位`（`web/src/features/settings/knowledge/format.ts:133`）、`3–6 星`（`web/src/features/tasks/editor/MapControls.tsx:175`）。
- 句末句号：校验类错误 18 带 / 8 不带（不带例：`web/src/features/tasks/editor/JsonControl.tsx:59` JSON 格式尚未完整或无效）；Toast 1 带 / 23 不带（带的是 `web/src/features/tasks/queue/QueueView.tsx:128` 已取消所有待执行条目。）。
- 冒号层级：`web/src/features/tasks/composer/use-submit-pipeline.ts:30` 一句话用了「（504）、；。」四种标点。
- 做对的部分：`「」` 全库 82 条统一下来，没有 `""` 混用；`…` 统一用单字符（64 条），唯一 `...` 在 cURL 示例里（`web/src/features/api-console/utils.ts:429`），属正常。

### 2.8 四类固定场景

**空状态**：title 三种开头（`还没有` 13 / `没有` 5 / `暂无` 2）。`web/src/features/dashboard/DeviceScreenshot.tsx:129` 暂无截图、`web/src/features/logs/LogList.tsx:175` 暂无匹配的历史或实时日志 属少数派。description 多数是说明书或原理（`web/src/features/api-console/ApiConsolePage.tsx:560`、`web/src/features/tasks/history/HistoryView.tsx:86` 执行过的流水线会出现在这里。）。好的样板是 `web/src/features/dashboard/QuickActions.tsx:65-67`：还没有定时任务 +「先编排一组任务并保存」+ 按钮。

## 三、界面文案规范

### 按钮
1. 动词短语 2–6 字，不带「请/点击」。反例 `web/src/components/ui/confirm-dialog.tsx:27`「确认」；正例 `web/src/features/settings/NotificationChannels.tsx:126`「删除通道」。
2. 同一动作全站同一动词。反例 `CurrentPipelineCard.tsx:100`「停止任务」 vs `QueueView.tsx:158`「停止流水线」；正例：统一「停止流水线」。
3. 破坏性按钮必须带对象。反例 `web/src/features/tasks/composer/TaskComposer.tsx:91`「确认并开始执行」；正例「开始执行」。
4. 按钮内不放数量/统计。反例 `QueueView.tsx:197`「清空 ${count} 条待执行」；正例「清空待执行」，条数写进描述。

### 标签
1. 名词短语，不写句子。反例 `maa_api/services/settings_schema.py:68`「原子操作授权确认等待时长（秒）」；正例「屏幕操作授权确认等待时长（秒）」（对齐界面 `web/src/features/agent/ConfirmationCard.tsx:56` 的「会话级屏幕操作授权」）。
2. 单位用全角括号追加，全站统一：正例 `maa_api/services/settings_schema.py:51`「每日更新检查时间（小时）」。
3. 后端 `label` 就是界面标签、`description` 就是展开说明，改后端等于改界面（证据：`web/src/features/tasks/editor/FieldEditor.tsx:95` 展开说明开关）。

### 空状态
1. 首句统一「还没有 X」。正例 `web/src/features/settings/NotificationChannels.tsx:216`「还没有通知通道」；反例 `DeviceScreenshot.tsx:129`「暂无截图」、`LogList.tsx:175`「暂无匹配的历史或实时日志」。
2. 第二句给"怎么开始"，不给原理。反例 `ApiConsolePage.tsx:560`「从左侧接口列表选择后，这里会按 OpenAPI 生成请求表单。」；正例「从左侧选一个接口开始」。
3. 不写「服务端/接口没有返回」。反例 `PipelineDetail.tsx:51`；正例「任务明细暂不可用，稍后重试」。
4. 整个空状态 ≤2 行、≤30 字，必须带一个动作按钮。正例 `QuickActions.tsx:65-67`。

### 错误提示
1. 结构固定：**发生了什么 + 你可以做什么**。正例 `web/src/features/schedules/errors.ts:69`「已有同名的定时任务「X」，请换一个名称。」；反例 `AgentPage.tsx:431`「Agent 对话失败。」。
2. 不复述「失败」。反例 `QueueView.tsx:108`「操作失败：{消息}」；正例「{消息}」或「暂停队列失败：{消息}」。
3. 兜底不许出现英文与 JSON。反例 `web/src/api/errors.ts:68`、`web/src/features/updates/types.ts:294`；正例「请求超时，请重试」。
4. 表单项校验统一「请…」+ 句号。正例 `web/src/features/settings/schema.ts:131`「请填写数值。」；反例 `web/src/features/tasks/editor/JsonControl.tsx:59`「JSON 格式尚未完整或无效」（缺句号）。
5. 状态码放句中，一屏最多一个：正例「没有权限执行此操作（403）」。

### 确认弹窗
1. 标题 = 动词 + 对象 + ？。正例 `web/src/features/settings/NotificationChannels.tsx:124`「删除通知通道「X」？」；反例 `QueueView.tsx:183`「停止当前并执行此条？」（「此条」→ 换成流水线名）。
2. 描述 ≤40 字，只写后果不写机制。正例 `QueueView.tsx:196`「将取消 N 条待执行流水线，正在运行的不受影响。」；反例 `QueueView.tsx:184`（103 字）。
3. 不可撤销才写「无法撤销／无法恢复」，且全站同一句。正例 `NotificationChannels.tsx:125`。
4. confirmText 与 cancelText 成对反义；危险操作的取消按钮用「保留／继续…」，不用裸「取消」。正例 `QueueView.tsx:169-170`「取消这条 / 保留」。

### Toast
1. 完成态「已 + 动词」，≤15 字，**不加句号**。正例 `web/src/features/settings/NotificationChannels.tsx:137`「已删除「X」」；反例 `QueueView.tsx:128`「已取消所有待执行条目。」。
2. 不放需要阅读的解释。反例 `PushNotifications.tsx:120`；正例「已启用推送」。
3. 失败提示才用 error，并给下一步。正例 `web/src/features/dashboard/QuickActions.tsx:42`「运行失败：{消息}」。
4. 同一动作的按钮、toast、确认弹窗用同一动词。反例 按钮「清空待执行」（`:277`）/ toast「已取消所有待执行条目。」（`:128`）。

### aria-label
1. 动词 + 对象（+ 序号），读屏可区分。正例 `web/src/features/settings/ChannelEditor.tsx:148`「删除请求头 ${index+1}」；反例 `AgentPage.tsx:691`/`:707` 同页两个「Agent 对话」。
2. 同页不得重复。正例「Agent 会话列表」「Agent 消息区」。
3. 状态类 aria-label 带当前值。正例 `QueueView.tsx:217`「队列状态」配可见文本「队列运行中／已暂停」。
4. 不以「…」结尾，不加句号。
