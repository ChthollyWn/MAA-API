面向对象：终端用户看不到、但维护者每天要读的文本：源码注释、docstring、内部常量、脚本输出、docs/ 正文与标题。

## 0. 结论

**本仓库开发向书面的 AI 腔是「重」，比界面文案重得多。** 界面文案的破折号只有 30 条，开发向有 134 条；界面的粗体 140 条，开发向 216 条；而完全没进扫描器的 docs 正文里还压着 **1940 处粗体、508 处破折号**。这不是「个别措辞」，是已经固化成文体的写法：**先给断言加粗，再用破折号补一句解释，最后用「而不是 B」把话钉死**。

病灶按危害排序：

| # | 病灶 | 规模 | 为什么是病 |
|---|---|---|---|
| 1 | 破折号 `——` 当冒号/逗号 | 开发向 134 + 注释 86 + docs 正文 508 | 中文里 `——` 是有标记性的停顿；每段一处就变翻译腔 |
| 2 | 「A 而不是 B」对照强调 | 开发向 83 + docs 正文 279 | 默认读者不傻，反复否定一个没人主张的 B 是自我辩护 |
| 3 | 加粗 + 小标题 + 表格三件套 | 开发向 216 + docs 正文 1940 | 处处加粗 = 处处不加粗，扫读锚点失效 |
| 4 | docstring 写实施流水账与自辩 | 42% 的模块 docstring 带里程碑号（134 个中 56 个） | 注释回答「为什么这么写」，不回答「谁在哪个里程碑改的」 |
| 5 | 绝对化规定腔 | 开发向 67 + 注释 66 + 测试 59 | 「绝不一律务必」用在契约上是对的，用在叙述上是虚张声势 |
| 6 | 自指式讲解腔 | 开发向 50 + 注释 17 + docs 正文 89 | 「本模块/这里不/下面这」是讲解视频的口吻 |
| 7 | probe 报告 emoji 与总结腔 | 3 个脚本 11 处 emoji + 大段自评 | 报告是取证产物，`✅⚠️❌` 与「结论速览」让它像 PPT |

## 2. 逐类病灶

### 2.1 破折号 `——` 当冒号/插入语（164 条；注释 86、测试 32、docs 正文 508）

**判据**：句子里 `——` 能被「：」「，」「（…）」无损替换 → 是病。`术语 —— 定义` 的词典体、《》与引号内的原文引述、以及真正表示语气转折的 `——` 不算。

**样例**
- `maa_api/core/worker.py:66`｜`# GC 回收，回调线程里的 ``ctypes.cast`` 就会解引用悬垂地址 —— 直接崩内核。`
- `maa_api/core/enums.py:7`｜`不要"顺手"改成连号 —— 照连号硬编码会把 ``ConnectionInfo`` (2) 当成 ``TaskChainError``。`
- `maa_api/core/supervisor.py:45`｜`——「连续崩溃」要跨自动重启累计，否则「崩溃 → 重启 → 又崩」的循环永远到不了上限。`
- `maa_api/core/client.py:35`｜`**不进队列等待** —— 让调用方立刻拿到明确状态，而不是挂在一个可能永远不就绪的内核上。`
- `maa_api/agent/runtime.py:2173`｜`不看调用 id —— 同一批调用每轮都会拿到新的 id，用 id 会让指纹永远不同。`
- `maa_api/agent/questions.py:546`｜`—— 这是 400 而不是 409：请求本身（选了什么）不成立，与提问当前状态无关。`
- `docs/13-决策记录.md:53`｜`核实确认 MaaCore 的 OCR 没有独立 C API —— 内核内置 libfastdeploy_ppocr，但只能通过 tasks.json 的 task 定义间接触发`
- `docs/README.md:161`｜`没有其他文件类型——现有代码拉取的那一个文件已经是这条通道的全部内容。`

**改法**：冒号优先（`A：B`，B 是 A 的解释）；因果用「，」+「所以/因此」；让步用「（…）」；`——` 只留给真正需要停顿的地方，全篇 ≤ 3 处。同句里已经有一个 `——` 时，第二个必须删。

### 2.2 「A 而不是 B / 而非 / 才是」对照强调（93 条；注释 86、测试 31、docs 正文 279）

**判据**：B 是读者本来就可能误认的选项 → 保留（如 `fail loud 而不是静默跳过`）。B 是没人主张的稻草人（「笼统的请求失败」「盲目录入」）→ 删。判据落地成一句：**看这个 B 在正文/规格里有没有出现过；没出现过就别否定它。**

**样例**
- `maa_api/agent/llm.py:31`｜`所以这条映射是用户唯一能看出「窗口装不下」的地方，而不是笼统的请求失败。`
- `maa_api/agent/llm.py:219`｜`把上游的拒绝翻译成可读的 400，而不是笼统的「请求失败」。`
- `maa_api/agent/knowledge/__init__.py:465`｜`# 构造即加载：内置文件坏了要在装配处（启动）就炸，而不是等第一次请求`
- `maa_api/agent/runtime.py:1679`｜`# 标题跟着会话自己的模型走，而不是当前设置里的模型：会话的 model/base_url 是`
- `maa_api/api/routers/notifications.py:197`｜`# 幂等重放返回 200 而不是 201：契约里必须显式声明，否则生成的类型缺这一档。`
- `maa_api/core/asst_protocol.py:201`｜`声明成 ``Callable`` 属性而非方法的原因见模块 docstring。`
- `maa_api/services/callback_translator.py:121`｜`内层同键优先——它才是本次事件自己的数据。`
- `docs/13-决策记录.md:33`｜`这是一次破坏性变更，选它而非"新接口用新格式、旧接口保持兼容"。`

**改法**：直接陈述事实（`把上游的拒绝翻译成可读的 400`）。确实需要对比时，把 A、B 平行写成两句，或写成「B 的错误后果」，让读者自己选。`才是` 全部删。每个模块的对照句上限 1 处。

### 2.5 加粗断言 + 小标题分节 + 表格三件套（粗体 356 条；docs 正文 1940 处）

**判据**：一段文字若「加粗领句 + `====` 或 `###` 小节 + 一张表」齐全，且表格只有 2–3 行、加粗句就是该节全部内容 → 三件套空转，压成一段话。粗体只允许出现在三种位置：**决策结论**、**脚注级警告**、**表格里的状态词**。

### 2.6 docstring 写实施流水账与自我辩解

这类命不中任何正则，靠结构判断：**出现里程碑号 + 「实测」+「返工/照抄/本卡」+ 「…才是对的/原因见上」** 就是流水账。量化：`maa_api/` 134 个模块 docstring 里 **56 个（42%）带里程碑号**，函数 docstring 954 条里 91 条（10%）；注释行 1557 条里 63 条（4%）。越靠模块头越像日记。

**样例**
- `maa_api/main.py:420`｜`独立成函数是为了可单测：直接调用即可断言文案，不必依赖 ``TestClient`` 线程里的 日志捕获（M3-09 实测 caplog 也能捕到，但直接调用更稳、更快）。`
- `maa_api/settings.py:311`｜`#: 同上：未识别的段/键忽略（``smtp`` 段在本卡不建模，M6 的通知配置另建模型）。`

- `maa_api/core/supervisor.py:825`｜`为什么必须换（M1-08 实测，Python 3.13.3）：`
- `maa_api/agent/runtime.py:196`｜`…而不是 try/except ``TypeError`` —— 后者会把 工厂内部的真实类型错误当成「旧签名」吞掉，然后错误地在更少的参数下重试。`
- `maa_api/core/asst_protocol.py:201`｜`声明成 ``Callable`` 属性而非方法的原因见模块 docstring。`
- `scripts/probe_sqlmodel_alembic.py:1404`｜`> **M2-14 修正（2026-09-16）**：§2 与 §6.5 原先记录的 auto_vacuum「唯一生效放置」只写了…该缺陷由 **M2-04** 实测发现（照抄后 alembic_version 行为空…）`

## 3. 本仓库书面中文规范（注释 / docstring / docs / 提交信息）

### 3.1 长度

| 位置 | 上限 | 现状 |
|---|---|---|
| 行内注释 | 单块 ≤ 2 行、单行 ≤ 100 字符 | 最长行 117（`api/errors.py:255`）与 129（`core/supervisor.py:94`） |
| 函数 / 类 docstring | ≤ 8 行，只写参数语义、返回值、抛出的错误 | 均值 3.7 行，最长 28 行（`db/repositories/resource.py`） |
| 模块 docstring | ≤ 15 行，三段：职责 / 契约 / 边界 | 均值 11.8 行，最长 83 行（`api/errors.py`） |
| docs 单节 | ≤ 60 行；超过就拆文件 | 最长 116 行（`docs/05 §7.3`），其次 92 行（`docs/09 §2`）、85 行（`docs/13 §8.12`） |
| 提交信息主题 | ≤ 50 字，正文 ≤ 5 行 | 见 `git log` |

### 3.2 句式

1. **陈述优先**：说代码做了什么，不说它「不是」什么。
2. **一句一个意思**，逗号不超过 3 个；超过就断句。
3. **不解释常识**：读者是会读代码的人。「否则生成的类型会缺一档」有用，「信息不丢」没用。
4. **不劝告**：删「千万别」「切记」「其余都别往这里塞」。
5. **不承诺**：「永远」「绝不」「一律」只在能被测试或断言钉住时使用。
6. **不排比**：连续三个「XX 负责…，YY 负责…，ZZ 负责…」压成一句。

### 3.3 该写 / 不该写

**该写**：为什么这样做（反直觉的取舍、被否掉的替代方案及其失败模式）、调用方看不见的约束（顺序、幂等、线程/协程边界、资源归属）、外部依据（`docs/05 §4.1`、内核版本、实测结论）、失败时的表现。

**不该写**：里程碑号与工期（`M3-09 实测`、`本卡`、`返工`）；「本模块/这里/下面这」；对读者的说服与自辩（「更稳、更快」「这才是对的」）；完整规格的复制粘贴（指向 docs 即可）；用表格包装的 2 行内容；同一句话在模块 docstring、函数 docstring、测试名里各说一遍。

### 3.4 术语与标点

- **术语表**（统一使用，不造同义词）：`内核`（不写 MaaCore 引擎/native 层）、`渠道`、`会话`、`落库`、`生效值`、`幂等`、`契约`、`边界`、`fail loud`、`流水线`、`确认`（不写「审批」）、`提问`（agent 的 ask_user 链路）、`原子操作`。
- **破折号**：一篇文档 ≤ 3 处，一个模块 ≤ 1 处；优先用 `：`。
- **引号**：正文统一 `「」`，代码块与 JSON 内保持 ASCII `"`。现状不统一：docs/01、02、08 全用 ASCII `"`（28/32/358 处），docs/13 混用（`「」` 710、ASCII `"` 271，如 13:9、13:35、13:85）。
- **省略号**：正文用 `…`，不写 `……`。
- **数字与单位**：ASCII 数字，前后不加空格（`15 分钟`、`10 次/分钟`）；范围用 `~`。
- **emoji**：源码注释、docstring、docs 正文一律不用。一次性取证报告可用文字标记替代。
- **中英混排**：术语首次出现给英文原形，之后只用中文；不写「we」「Let's」。

### 3.5 禁止清单（可写进 CI 的 lint 规则）

```
1. 源码注释/docstring 里出现 —— 且后接完整分句（\n\s*—— 开头同理）
2. 出现 「而不是 B」「而非 B」，且 B 未在同文件出现过
3. 出现 才是|才是真正
4. 出现 本模块|本函数|本类|本文档|这里不|下面这|上面这
5. docstring 里出现 M\d+(-\d+)?（例外：迁移文件头部的版本溯源）
6. docstring 里出现 实测|返工|本卡|照抄
7. OpenAPI description 字符串里出现 **
8. 任何 .md/.py 里出现 ✅|❌|⚠️|🔴|🟢
9. 正文（非代码块）出现 ASCII 双引号包裹中文
10. 注释行长度 > 100
```
