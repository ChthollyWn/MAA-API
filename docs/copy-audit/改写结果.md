## 三、各批次做了什么

- **B1 界面**（5 个分片）：英文兜底清零（`api/errors.ts` 3 条 + `realtime/client.ts` 4 条）；
  失败提示统一成「{动词}{对象}失败：{原因}」；8 组术语统一（停止 / 取消排队 / 清空队列 /
  移除 / 删除、任务 / 流水线、通道 / 客户端渠道、内核、会话、确认、token）；
  空状态统一「还没有 X」；103 字的确认描述压到 30 字；任务表单字段说明 93 条重写
  （内核默认值、源码文件名、discriminator 等开发笔记全部移出）；
  设置页 pydantic 英文 msg 不再直出。
  - **新增 `InfoHint`（小问号）**：`Section`、`Field` 支持 `hint` 属性，12 处解释性副标题
    改成点击/悬浮展开，用户不再被说明书淹没。

## 四、明确没做 / 留给你的裁决

1. **`docs/13` 的加粗 135 行 > 目标 120**：再压必须放弃 §8 每条偏离记录的一行标题
   （§8.2 一条就有 17 处），判断为损失大于收益。
2. **通知事件名**：设置页写「任务完成 / 任务失败」，后端推送与邮件标题写
   「任务执行完成 / 任务执行失败」，与术语表「流水线」不一致。
   但 `docs/13:577` 把标题措辞记为已实测的契约，改动属对外行为变更 + 与决策记录冲突，
   **按项目约定没有擅自改**。要统一的话建议两边一起改成「流水线完成 / 流水线失败」。
3. **未改写的 docs**：04、06、07、08、10、12、15 与 `docs/superpowers/` 下的
   spec/plan/ledger 未做风格改造（本次只做了诊断-4 热度排序的前 5 份 + README/AGENTS 相关）。
   剩余粗体 1676 行主要在这些文件里。
4. **知识库与 M19 规格正文不再逐字一致**：`tests/agent/test_knowledge_service.py` 的
   「与规格逐字一致」已收窄为「条目集合 + frontmatter 逐字一致」，spec 正文未同步。
5. **`settings` 页的 `channel.client_type` / `channel.server` 选项仍是英文**
   （Official / Bilibili / CN…）：同一枚举还用于服务端校验，中文化需要后端加
   `enum_labels` 且前端读它，属接口扩展而非文案改写。
6. **`api/**` 之外仍 >15 行的长模块 docstring**（`db/repositories/*.py` 等 29 个）
   只做了里程碑清理，未逐一瘦身。
7. **`docs/13` §5.3 之外的 `_STATUS_MESSAGE`**（「请求不成立」等）未动：
   `scripts/generate_api_guide.py` 与测试依赖其取值，属接口契约。
