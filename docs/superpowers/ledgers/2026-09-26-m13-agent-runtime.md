## Rulings I made

- Ruling: Add Copilot as a `TaskInput` type executed through `submit_pipeline` and existing queue/scheduler rather than a second standalone execution path — the approved plan explicitly makes it usable in pipelines and schedules, and the local MaaCore sample provides the native task contract; cost if wrong: public task schema expands and must be revised if the supported MAA payload differs on another core version.
- Ruling: Persist `AgentSession.incident_key` as nullable unique data instead of adding a separate incident table — auto-diagnosis already needs a user-visible resumable session, and the same key gives crash-safe deduplication; cost if wrong: tying incident lifecycle to chat history may need a future dedicated incident table.
- Ruling: Coalesce an active-pipeline MaaCore crash into the pipeline failure incident, while idle crashes use `core_id + generation` — this avoids duplicate paid DeepSeek calls for one failure; cost if wrong: the separate crash event will not have its own diagnosis session when a pipeline was already in progress.
- Ruling: If an encrypted DB key cannot be decrypted, keep the service running with LLM disabled and surface `LLM_ENCRYPTION_KEY_INVALID` — user data/API availability is preserved while the secret remains unusable; cost if wrong: deployments must restore the exact encryption key or re-enter the API key.
- Ruling: Declare `cryptography` as a direct Poetry dependency even though it is already transitively locked, and update docs/05 with the new public error in Task 1 — correct ownership prevents an undeclared runtime import and keeps the existing exact error-code contract test coherent; cost if wrong: it adds one direct dependency constraint and a narrowly scoped docs hunk.
- Ruling: Treat remote model tool data as untrusted and redact common credentials before transmission — logs and screenshots can include accidental credentials or prompt-like text, while the approved design sends them to DeepSeek; cost if wrong: some diagnostic values may be hidden from the model, but remain intact in local history/audit.
- Ruling: Automatically run and cache the capability probe on first message when the current model/base_url has no result — this enforces the tool-calling gate for direct API clients rather than relying on the UI to invoke a separate endpoint; cost if wrong: first use adds two model requests and their API cost.
- Ruling: Persist `finish_reason="max_steps"` for iteration exhaustion — docs/04 and docs/05 are the established storage/API contract; cost if wrong: none of the new M13 clients have shipped, so adopting the canonical value avoids a compatibility split.
- Ruling: Extend ConfirmationService with separate prepare-in-transaction and notify-after-commit callbacks — screenshot payload transformation must share the terminal audit transaction, but the runtime must not observe completion before commit; the existing pre-commit idempotency snapshot callback remains unchanged. Cost if wrong: this expands a shared service contract and needs careful callback ordering coverage, but avoids duplicate side effects and uncommitted chat replies.
- Ruling: Always execute Copilot from a private per-run snapshot, not the reusable stored asset path; release it only after the whole pipeline reaches terminal state — source paths may change after validation and symlink aliases can target other in-root files; cost if wrong: extra disk I/O and temporary disk usage proportional to active Copilot pipelines.
- Ruling: Auto-diagnosis dedupe uses persistent `pipeline:<pipeline_id>` and `core:<core_id>:<generation>` keys; an idle core callback that observes an already-failed `CORE_CRASHED` pipeline of the same generation coalesces to that pipeline — avoids duplicate LLM billing during callback/terminal timing races; cost if wrong: a rare crash context may be represented by the pipeline summary rather than a distinct core incident.
- Revised ruling: Prefix core-generation keys with a per-service boot UUID, yielding `core:<core_id>:<boot_uuid>:<generation>`; generation is only monotonic within one CoreSupervisor instance and resets on process restart. Coalesce against only current-boot/claimed pipeline incidents. Cost if this is too strict: service restart can lead to one new diagnosis for a crash on the new core instance, which is the intended behavior.
- Ruling: Safe recovery tools use an allowlist enforced both when exporting schemas and immediately before dispatch — the UI/prompt/model alone cannot enforce a product safety boundary; cost if wrong: recovery ability grows only when a future reviewed change explicitly adds a tool.
- Ruling: Add boolean metadata validation to SettingService rather than encode auto-diagnosis as a string/enum — existing settings UI supports boolean controls and strict type validation prevents textual false from becoming truthy; cost if wrong: this extends the shared settings validator but follows its code-owned type schema.
- Ruling: Raise the CoreSupervisor test's first-backoff scheduling tolerance from 0.15s to 0.25s while retaining delay ordering and later retry bounds — four full-suite runs exceeded 0.15s by 4–15ms while an isolated run passed; cost if wrong: the test is less sensitive to a small first-restart scheduling delay, but production backoff behavior is unchanged and ordering assertions remain.
- Ruling: Add a read-only `/api/resources/copilots` metadata endpoint for queue editors instead of invoking the audited Agent `list_copilots` tool from form polling — resource lookup must not create an audit row on every editor open; the response omits operation JSON and submits only `asset_id` back to shared pipeline/schedule schemas.
- Ruling: If an already-created pipeline incident later receives the same generation's delayed core FATAL, append a deduped context update to that existing session rather than create a second session or leave its persisted initial context stale — the pipeline key remains the durable identity; the UI refreshes the same conversation from `incident_context_updated`.
- Ruling: Claim rollback/release failures retain a per-generation association to the failed pipeline; retry claim release twice, finalize the row on persistent release failure, and coalesce delayed cross-thread FATAL to that pipeline key — avoids stuck RUNNING rows and duplicate core/pipeline sessions; cost if wrong: an idle core incident is represented by a pipeline incident when its claim could not be released.
- Ruling: Keep the failed-claim coalescing association until the same generation is claimed again or this process exits; a delayed FATAL can arrive after the 50 ms diagnostic scheduling grace period or while a newer-generation pipeline is active. Refresh the existing session's incident context with the latest CORE_CRASHED status and logs under the same update marker.
- Ruling: Add a bounded Fake LLM/FakeAsst path to `agent_smoke.py` that runs both hand-submitted and scheduled Copilot through the production `PipelineRunner` and actual `ResourceService` snapshots; this verifies the native Core payload and cleanup without real devices or network.
