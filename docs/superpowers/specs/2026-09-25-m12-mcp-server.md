# M12：MCP Server 规格

## 目标与边界

M12 在 M11 的 `ToolRegistry` 与 `ConfirmationService` 之上交付 MCP Streamable HTTP 服务和本机 stdio 瘦代理。Claude Desktop、Cursor 等 MCP 客户端可发现并调用工具，所有调用仍由 FastAPI 主进程执行并写入共享审计。

采用官方 `mcp` Python SDK，锁定已在本机缓存核验 API 的 `mcp==1.13.1`。当前网络受限，未能核验上游更新；此次不声称该版本为最新版。

本里程碑不实现 LLM 对话循环、会话消息写入或 Copilot 运行器；不做 Tailscale FQDN 部署验收，也不把 scope 当作权限边界。

## 已确认决策

- Streamable HTTP 端点为 `/mcp`，服务挂载在 FastAPI 同端口。FastAPI 宿主 lifespan 必须启动并关闭 MCP session manager。
- MCP HTTP 在配置 `access_token` 时只接受 `Authorization: Bearer <access_token>`；缺失、格式错误或 token 不匹配按现有 `UNAUTHORIZED` 与鉴权失败限流规则处理。`Mcp-Session-Id` 只关联 MCP session，每个请求仍独立鉴权。沿用应用未配置 `access_token` 时免鉴权的既有全局模式。
- `scopes` 是逗号分隔的工具组筛选参数；缺省为 `status,pipeline,device,schedule,confirmation`。`raw`、`resource`、`ops` 仅在显式选择后可见。scope 同时限制 `tools/list` 和 `tools/call`，但任何持有有效 token 的客户端都可自行请求任意组，因此它不是授权边界。
- scope 名须属于已注册组；显式空值和未知组拒绝。解析时去重并按注册组规范顺序规范化。对未暴露组的直接调用与未知工具使用相同的 `TOOL_NOT_FOUND` 工具错误，避免泄漏隐藏工具清单。
- `transport_security.allowed_hosts` 读取 `mcp.allowed_hosts` 配置；默认允许 `localhost`、`127.0.0.1` 和启动时发现的 RFC1918 本机 IPv4 地址。操作者可显式追加 loopback/RFC1918 IPv4 Host；M12 拒绝非 LAN FQDN，Tailscale FQDN 配置留到 M15。SDK 校验的条目使用 `host:*` 形式。该列表只用于 DNS rebinding / Host 校验，不改变监听地址或认证。
- stdio 代理不创建 MaaCore、数据库或 ToolRegistry。它启动时以 HTTP 获取工具清单，动态注册 schema；每次调用经 FastAPI 的专用 MCP invoke API 转发。
- 默认 scopes 加入 `confirmation` 是已确认的契约修正：该组只有只读 `check_confirmation`，但 pending 调用必须能依提示查询结果。其余高风险组仍需显式选择。
- MCP 确认调用复用 `ConfirmationService.invoke_mcp`，最多短等 25 秒。未决确认作为 pending 工具结果返回，之后 `check_confirmation` 只读查询持久状态；不依赖 elicitation。

## HTTP 与 stdio 契约

### Streamable HTTP

- 使用 SDK 的低层 `mcp.server.Server` 与 `StreamableHTTPSessionManager` 提供 `initialize`、`tools/list`、`tools/call`；其 Streamable HTTP ASGI handler 挂在 `/mcp`。
- `tools/list` 和 `tools/call` 读取 SDK request context 中当前 ASGI 请求的 URL；每个请求按自己的 `scopes` query 参数筛选，避免 FastMCP 静态工具列表及其跨 session 全局工具缓存造成 scope 串用。
- 为 `TransportSecuritySettings` 同时生成与允许 Host 对应的 HTTP/HTTPS Origin 模式，保留 SDK 对带 Origin 请求的 DNS rebinding 防护。
- 工具 schema 来源为主进程 `ToolRegistry`。工具调用构造 `ToolContext(caller=MCP, scopes=当前规范 scope)`，经 `ConfirmationService.invoke_mcp` 执行。
- MCP mounted ASGI app 与 FastAPI 宿主共享同一个 `app.state`，让现有工具 handler 继续访问宿主服务；每次调用使用主进程 SQLAlchemy session factory 创建/关闭独立 async DB session，并沿用请求追踪 id。
- `tools/call` 使用 SDK 低层 handler 构造 `CallToolResult`，以便业务错误设置 `isError=true` 并保留 `structuredContent` 的 `code`、`message` 与 `details`。认证与协议会话错误由传输层处理。
- `tools/call` 仅可调用当前 scope 所含组的工具。`confirmation` 默认可见，确保 pending 结果可继续查询。

### stdio 瘦代理

- 默认主服务地址为 `http://127.0.0.1:8002`；配置 `MAA_API_BASE_URL` 可覆盖。
- `MAA_APP_ACCESS_TOKEN` 是可选 Bearer token；未设置时服务端沿用免鉴权模式。
- `MAA_MCP_SCOPES` 为逗号分隔 scope，缺省与 HTTP 默认一致。
- 启动时 GET `/api/agent/tools`，按 `group` 过滤，再把 `input_schema` 映射成 MCP input schema；工具调用 POST `/api/agent/mcp/tools/{name}/invoke`。
- invoke JSON 请求体为 `{"arguments": <对象>, "scopes": [<规范组名>]}`。该受保护路由把调用作为 MCP 来源交给共享确认服务并记录 scope；scope 是可见性和审计快照，不是权限凭据。
- stdio stdout 仅输出 MCP 协议帧。启动、HTTP、配置错误写 stderr；退出或关闭时关闭 HTTP 客户端与 MCP session。

## 审计与迁移

- `agent_audit.scopes` 为可空 JSON 字符串列表。新 MCP 调用保存本次规范 scope；REST、内置 Agent 和历史行保持 `null`。
- 添加向前 Alembic 迁移，upgrade 将该字段加为 nullable JSON，已有行无需回填；downgrade 删除该字段。
- 审计列表与详情 API 都返回 `scopes`。前端审计列表/详情在 MCP 记录上显示 scope；不增加 scope 筛选器。

## 配置与文档

- 增加只读 `mcp.allowed_hosts` 配置，支持 `config.yaml` 列表与 `MAA_MCP_ALLOWED_HOSTS` 逗号分隔覆盖，变更需重启生效。
- 同步 `config.template.yaml`、README 决策表、docs/04、docs/05、docs/10、docs/11、docs/12、docs/13 §8、docs/14 和 OpenAPI / TypeScript 生成产物。
- 修正 docs/05 stdio 进程内调用描述，与已确认的 HTTP 瘦代理架构一致。

## 验收

- MCP SDK 客户端可通过 `/mcp` 初始化、列出默认工具、调用安全工具，并在带 token 时通过 Bearer 完成认证；缺失或错误 Bearer 拒绝，session id 本身不授权。
- 默认列表包含确认查询且不含 raw/resource/ops；显式 scope 能展示并调用对应工具；未知、空 scope 和 scope 外调用按本规格拒绝。
- Host 校验允许 loopback、发现的/配置的 LAN Host，拒绝未允许 Host。
- 高风险 MCP 调用由前端确认流程处理；短等后 pending 可用 `check_confirmation` 查询，不会自动重放。
- stdio 子进程动态拉 schema、转发 invoke、传递 scope，并在 stdout 保持协议帧纯净。
- migration upgrade/downgrade、审计 API/UI 的 scope 展示、OpenAPI 快照、后端全套测试、前端检查与 MCP smoke 均通过。MCP smoke 成功末行输出 `SMOKE OK`。
