# M11 Agent 基座实施计划

> **执行方式：** 使用 `superpowers:subagent-driven-development` 分任务实现与审查；遵循 TDD。

**目标：** 交付可由 REST 调用的完整 Agent 工具基座、确认/授权、审计与对应前端。

**架构：** `ToolRegistry` 统一 schema、参数校验、策略执行和审计；工具只调用应用服务。确认记录及终态结果落库，REST 调用可同步等待或异步查询；前端订阅现有 WebSocket 事件展示确认和审计。

**技术栈：** FastAPI、Pydantic、SQLModel/Alembic、pytest；Vite、React、TypeScript、Vitest。

**规格：** `docs/11-Agent模块设计.md`、`docs/12-实施计划与里程碑.md`、`docs/README.md`、`docs/13-决策记录.md`、`docs/04-数据模型与持久化.md`、`docs/05-API规范与路由清单.md`。

## 全局约束

- 从 `refactor/v2` 的 `m11-agent-base` 分支实施；不建 worktree、不 push、不合入 `dev`；完成后 `--no-ff` 合回 `refactor/v2` 并打 `v2-m11`。
- 工具不得直接访问 `CoreClient`，必须复用应用服务；不提供任意 `adb shell`；鉴权沿用单 `access_token`。
- 会话授权默认 15 分钟、上限 60 分钟；启动时清除，显式关闭/切换/删除时撤销。没有内置会话的 REST/MCP 原子操作逐次确认。
- `trigger_screencap`、`back_to_home` 为 SAFE；其余原子操作适用会话授权。Copilot 与 schedule 的条件确认按用户确认的副作用映射。
- 高风险确认 10 分钟，授权确认 120 秒；MCP 调用短等 25 秒后返回 pending 由 `check_confirmation` 轮询；MCP 传输仍属 M12。
- M11 提供会话 CRUD、消息查询、授权接口；消息写入/LLM 循环和会话授权提示条留 M13。
- 后端验证命令长输出重定向文件，只汇报退出码和必要尾部；主 agent 在验收前亲自重跑后端测试。

## 任务

### Task 1：Registry 与策略接口

**文件范围：** `maa_api/agent/registry.py`、`policy.py`、`tests/agent/`。

- [ ] 固定接口：`ToolDefinition(name, group, risk, description, params_model, handler)`；`ToolContext(caller, session_id, request_id, request, db_session)`；`ToolRegistry.register/get/list/validate/execute`；`PolicyEngine.evaluate(definition, arguments, context) -> PolicyDecision`。
- [ ] 先写失败测试，锁定工具元数据、Pydantic 参数校验、风险判断、SAFE 例外、原子会话授权与无会话逐次确认。
- [ ] 实现 `ToolContext`、工具 schema 导出、按名执行与策略决策；策略覆盖消耗/破坏参数、Copilot 和 schedule 映射。
- [ ] 验证注册重复、未知工具、参数错误、授权到期/撤销与调用者差异。

### Task 2：状态与流水线工具

**文件范围：** `maa_api/agent/tools/`、`maa_api/db/models.py`、新迁移、callback/statistics service 与相关 `tests/agent/` / `tests/services/`。

- [ ] 该组模块导出 `register_tools(registry: ToolRegistry) -> None`；Task 3–4 使用相同入口，Task 5 统一聚合。每个 handler 接收已校验的 Pydantic 参数与 `ToolContext`，返回 JSON 可编码值。
- [ ] 先写失败测试，再实现 status 组与 pipeline 组：状态、截图、版本、日志、关卡、掉落统计、任务类型、流水线、队列、提交/停止/修改/取消。
- [ ] 将 `StageDrops` 与 `SanityBeforeStage` 回调结构化持久化，使历史掉落统计不依赖展示日志文本；用 callback fixture 验证字段解析与按关卡/时间聚合。
- [ ] 只经现有应用服务、仓储或显式小型 service adapter；复用队列优先级和参数模型。

### Task 3：设备与原子操作工具

**文件范围：** `maa_api/agent/tools/`、相关 `tests/agent/`。

- [ ] 先写失败测试，再实现 device/raw 工具组：设备状态/扫描/重连、截图触发、点击/滑动/长按/输入/按键/回主界面。
- [ ] 复用 M5 的 `operation_lock` 与 M6 `DeviceManager`/MaaCore app service；不直接访问 `CoreClient` 或接受任意 ADB 命令。

### Task 4：资源、运维与定时任务工具

**文件范围：** `maa_api/agent/tools/`、相关 `tests/agent/`。

- [ ] 先写失败测试，再实现 Copilot 上传/列表、基建方案、自定义 task、更新与 schedule 工具组。
- [ ] Copilot 上传做 schema 校验；自定义 task 满足独立目录、`Custom_` 前缀、加载失败回滚并重载；schedule 新建/修改仅在任务含消耗参数时确认，删除 schedule 不确认。
- [ ] 不注册 `run_copilot`。本地没有将 Copilot JSON 交给 MaaCore 执行的应用服务或已定义参数契约；用户决定将真实执行器留作待办，不能用普通 Fight 代替。
- [ ] 仅调用现有 app service/repository；返回项目统一错误码及稳定的简短结果摘要。

### Task 5：确认、审计与 REST API

**文件范围：** `maa_api/agent/confirmation.py`、`maa_api/api/routers/`、`maa_api/db/models.py`、新 Alembic migration、相关 repositories、`maa_api/main.py`、settings/schema 与设置/路由测试。

- [ ] 先写 API/服务失败测试，覆盖 REST sync/async、确认 approve/reject/expiry、服务重启清 pending、重复应答、会话 CRUD/撤销和审计结果回查。
- [ ] 落地 ToolRegistry invoke、确认列表/详情/应答、审计分页/详情和会话 API；终态确认详情包含执行结果/错误与 `audit_id`。
- [ ] 按 docs/05 §10.1 支持 `POST /api/agent/tools/{name}/invoke` 的可选 `Idempotency-Key`：24 小时内同 key/同 body 重放返回原审计结果，不同 body 返回 `409 IDEMPOTENCY_KEY_CONFLICT`。
- [ ] 用独立 `agent_idempotency` 持久表保存 key、请求体哈希、audit id 与创建时间；先清理过期键，再以唯一约束收口并发重放，不给永久审计表加 24 小时有效的全局唯一键。
- [ ] 审计列表支持 `caller`、`tool_name`、`status`、`risk_level`、`since` 分页过滤，与 docs/05 §6.15 保持一致。
- [ ] 审计单行从 `PENDING` 只转一次至 `SUCCESS` / `FAILED` / `REJECTED` / `EXPIRED`，供异步调用最终回查；执行与确认状态需幂等，`confirmation_id` 与 `authorized_by_id` 互斥。
- [ ] 会话消息只读 API 到 M11 为止，`POST /messages` 暂不挂载。
- [ ] 设置页可配置常规确认超时（默认 10 分钟）、授权确认超时（默认 120 秒）与会话授权窗口（默认 15 分钟、最大 60 分钟）；服务启动时清空所有旧会话授权。
