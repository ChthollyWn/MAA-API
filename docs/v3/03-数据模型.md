# 03 数据模型

v3 的全部新表与改动列。列的写法、约定与测试要求先看 §1；每个里程碑的表在 §3 起按里程碑排列。spec 里引用表结构时以本文为准。

## 1. 约定（沿用 v2，必须遵守）

来源：`maa_api/db/models.py` 文件头注释与既有表。

- 表类写成 `class X(SQLModel, table=True)`，显式写 `__tablename__`。命名约定模板（ix/uq/ck/fk/pk）已在文件头设置，索引与约束名按模板生成，本文写出的名字就是生成结果。
- **主键**：对外资源用 `id: str = Field(default_factory=new_uuid, primary_key=True, max_length=36)`；高频追加表用自增整数 `id: int | None = Field(default=None, primary_key=True)`，并在 `__table_args__` 末尾加 `{"sqlite_autoincrement": True}`。
- **时间**：一律 naive UTC，默认值 `utcnow()`，列用 `sa_column=datetime_column("<列名>")`。对外输出时补 `Z`（v2 `routers/agent.py` 约 241 行的写法）。
- **JSON 列**：用 `json_column(name, nullable=..., server_default=...)`；只整体赋值，不原地修改。
- **TEXT 列**：用 `text_column(name, nullable=...)`。
- **枚举列**：存字符串加 `max_length`（状态 16，种类与角色 24，错误码 48），不用 `sa.Enum`。取值在 `maa_api/domain/enums.py` 定义为 `StrEnum`，默认值写枚举成员。
- **外键**：`Field(foreign_key="t.id", ondelete=...)`。随父对象消亡的用 `CASCADE`，引用关系用 `SET NULL`。
- **索引**：高频写表每张不超过 3 条；低基数列只作复合索引的首列。
- **迁移**：文件名 `NNNN_<snake>.py`，`revision` 等于文件名主干，`down_revision` 指向上一条；当前 head 是 `0040_question_expiry_historical`。加可空列直接 `op.add_column`；改约束或删列用 `op.batch_alter_table(t, copy_from=<本迁移视角的 sa.Table>)`；数据迁移用 `op.execute`；不可逆的降级写显式 no-op 并注释原因。生产代码禁止 `create_all`。
- **布尔列**用 `server_default=sa.false()` / `sa.true()`，否则已有行加列会失败。

### 1.1 每次动表必须同步的测试

| 测试 | 要改什么 |
|---|---|
| `tests/db/test_models.py` | `BUSINESS_TABLES`（整集相等）、`EXPECTED_INDEXES`、外键清单、TEXT/JSON 列清单 |
| `tests/db/test_initial_migration.py` | 一般不用改；它比对迁移结果与模型元数据、索引清单、可重复升级、降级到底再升级、离线渲染。FTS5 虚拟表与触发器不在元数据里，M76 要在这里加排除 |
| `tests/db/test_<迁移名>_migration.py` | 每条新迁移一个新文件：在上一版 schema 上造数据，升级后断言新列、默认值、数据迁移结果；降级后断言恢复 |
| `tests/domain/test_enums.py` | 新增或改动的 `StrEnum` 都在这里整表钉死，必须同步 |

### 9.4 FTS5 虚拟表（迁移里用原生 SQL 建）

```sql
CREATE VIRTUAL TABLE knowledge_chunk_fts USING fts5(
  text, heading, content='knowledge_chunk', content_rowid='id', tokenize='trigram'
);
CREATE TRIGGER knowledge_chunk_ai AFTER INSERT ON knowledge_chunk BEGIN
  INSERT INTO knowledge_chunk_fts(rowid, text, heading) VALUES (new.id, new.text, new.heading);
END;
CREATE TRIGGER knowledge_chunk_ad AFTER DELETE ON knowledge_chunk BEGIN
  INSERT INTO knowledge_chunk_fts(knowledge_chunk_fts, rowid, text, heading) VALUES ('delete', old.id, old.text, old.heading);
END;
CREATE TRIGGER knowledge_chunk_au AFTER UPDATE ON knowledge_chunk BEGIN
  INSERT INTO knowledge_chunk_fts(knowledge_chunk_fts, rowid, text, heading) VALUES ('delete', old.id, old.text, old.heading);
  INSERT INTO knowledge_chunk_fts(rowid, text, heading) VALUES (new.id, new.text, new.heading);
END;
```

trigram 分词要求查询词至少 3 个字符；更短的查询走 `LIKE`（07 §2.3）。本机 SQLite 3.49.1 已实测支持 trigram（2026-11-02）。
