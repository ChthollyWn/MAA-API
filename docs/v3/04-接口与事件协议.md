# 04 接口与事件协议

v3 新增与改动的 REST 端点、SSE 事件、WebSocket 频道、错误码与配置项。每个里程碑只实现自己那一行；spec 与本文冲突时以本文为准。

## 1. 通用约定（沿用 v2）

- 鉴权：每条路由挂 `require_auth`；错误体 `{"error": {"code", "message", "details?"}}`；错误码到状态码的绑定在 `maa_api/domain/errors.py` 的 `ERROR_HTTP_STATUS`。
- operationId 规则是 `{tags[0]}_{函数名}`（main.py 约 367 行）。**v3 新端点一律用 tag `agent`**，函数名在 agent 组内唯一。
- 路由响应：v2 的 agent 路由返回 dict（由 `*_wire` 函数拼出）。v3 新路由**用 Pydantic 响应模型**（`response_model=`），模型放在路由文件内或 `maa_api/api/schemas/agent_v3.py`，这样形状会进 `web/openapi.json` 与前端生成类型。
- 分页：参数 `page`（≥1）、`size`（1–200），越界返回 `INVALID_PAGINATION`；返回 `{items, total, page, size}`。
- 时间：新字段一律 ISO 8601 带 `Z`。v2 WebSocket 里已有的 epoch 秒字段不改。
- 请求模型 `extra="forbid"`。
- 每加一条端点，必须同步：`web/openapi.json`（`.venv/bin/python scripts/dump_openapi.py`）、`web/src/types/api.d.ts`（`cd web && pnpm gen:api`）、现行路由清单（§7）。

## 3. SSE v3（总控与工单的消息流）

适用于 `POST /api/agent/orchestrator/messages` 与 `POST /api/agent/tickets/{id}/messages`。v2 会话的写端点与 SSE 已在 M72 删除，旧会话改为只读查看器。

- 帧格式与 v2 相同：`event: <名>\ndata: <紧凑 JSON>\n\n`，序列化前过 `redact_remote_data`。
- keep-alive：10 秒没有事件发一行注释 `: keep-alive\n\n`。
- 每个事件的 `data` 都带 `run_id`；嵌套运行（子代理）的事件也会出现在父会话的流里，用 `run_id` 与 `parent_run_id` 区分。
- 流什么时候结束：消费本条消息的那一轮运行发出 `run_end` 后，服务端关闭流。若本条消息进收件箱时已有运行在跑，流先转发当前运行的事件，再转发消费它的那一轮，直到那一轮结束。
- 客户端断开不会取消运行（与 v2 相同）。
- 总线上的内部事件 `message_persisted` 不进 SSE，只给 WS `agent_run` 广播器用（M70）。

|---|---|---|

## 5. 错误码

新增码必须同时改：`ErrorCode`（上一行写中文注释）、`ERROR_HTTP_STATUS`、现行接口清单 §4 的表与总数、`tests/domain/test_errors.py` 的计数常量。**本表之外不得新增错误码**；实施时发现 v2 已有同义码，停下来问。

## 6. 配置项

新增配置项必须同时改：`maa_api/settings.py` 的设置类与 `SETTING_KEYS`（config-only 的另加进 `CONFIG_ONLY_SETTING_KEYS`）、`maa_api/services/settings_schema.py` 的 `_FIELDS`（config-only 的不写）、`config.template.yaml`（带注释）、`tests/test_settings.py` 的 ENV_OVERRIDES 整表、`tests/test_vapid_settings.py` 的 config-only 集合（只在新增 config-only 键时）。环境变量名是 `MAA_` 加大写键名、点换下划线。

**不要用列表类型的设置项**：`setting_service._validate` 的类型表只有 string、integer、number、boolean 与端口专用的 integer[]；`string[]` 查表时抛 `KeyError`，PUT 返回 500 `INTERNAL_ERROR`（M64 实测，[13 §8.8](./13-决策记录.md)；既有的 `deployment.cors_origins` 也受影响）。需要列表时用多个布尔键。

`分组` 是 `_FIELDS` 的 `group`；`热生效` 是 `hot_action`。`IM 通道` 是 M85 新增的分组，要同步 `web/src/features/settings/sections.ts`。
