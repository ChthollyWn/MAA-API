## 目标

一张工单里可以有多个 Worker 按 DAG 协作，也能把这种协作存成可重复运行的工作流。

## 已定契约

- 表：`team_message`、`workflow`、`workflow_run`，[03 §12](../../03-数据模型.md)。
- 端点与函数名：[04 §2.5](../../04-接口与事件协议.md) 的 M96 行。
- 错误码：`WORKFLOW_NOT_FOUND`、`WORKFLOW_INVALID`。
- 配置：`teams.enabled` 默认 false，`workflows.enabled` 默认 true。
- 包：`agent/teams/`、`agent/workflows/`，[02 §4](../../02-系统架构.md)。
- 范围：[01](../../01-总览与范围.md) 的「代理团队、DAG 工作流编辑器」。

## 升格前要补

1. DAG 节点是代理名、工具名，还是已有工单种类。失败、人工确认、设备租约在节点之间如何传递。
2. `team_message` 谁能读、会不会进入别的代理的上下文。
3. 工作流运行与普通工单的关系：一张工单包一次运行，还是一个节点一张工单。
4. 编辑器放在哪一页，图的 JSON 形状是什么。
