### 8.1 分支改为从 dev 拉 docs-restructure，两个 v2 修复单独进 dev（M63，2026-11-03）

- 原定：spec 头部与 §5 T7 要求在 `v3-plan` 分支上做，最后整体 `git merge --no-ff v3-plan` 回 dev（m63 §0、§5 T7）。
- 实际：先把 `v3-plan` 上的两个 v2 修复（README 的 Tailscale 说明、手机端被动断流）`cherry-pick` 到 `dev`，再从 dev 拉 `docs-restructure`，`cherry-pick 319ccb2` 的 v3 文档后做 T2–T7；合并信息与 tag 不变。
- 理由：`v3-plan` 顶部混着与 M63 无关的 v2 修复，整体合并会把它们算进 M63；12 §3 要求从 dev 拉短分支。
- 影响：`dev` 多了两个 v2 修复提交；本地 `v3-plan` 分支在合并后删除，远端 `origin/v3-plan` 保留。

### 8.2 前置检查与 T1 计数的过时数字（M63，2026-11-03）

- 原定：§0 检查 2 期望 `docs/` 根 18 份文档；§5 T1 期望 `ls docs/v3/specs/m*.md | wc -l` 为 36（m63 §0、§5 T1）。
- 实际：`docs/` 根为 17 份（15 份编号文档 + README + DEFECTS）；spec 共 36 份但分两处（`docs/v3/specs/` 23 + `docs/v3/specs/todo/` 13）。
- 理由：§0 把 ENVIRONMENT.md 也算进了编号文档；T1 的计数命令写于 M86–M98 收进 `todo/` 之前。
- 影响：只影响验收命令的写法，交付物不变。

### 8.3 断链基线由 25 变为 26，检查跳过行内代码（M63，2026-11-03）

- 原定：§0 检查 4 与 §7 期望 `BROKEN 25`（m63 §0、§7）；附录 A 的脚本不区分行内代码。
- 实际：搬迁前 26 条既有断链（`docs/superpowers` 13 + `docs/copy-audit` 12 + `tests/fixtures` 1；copy-audit 比 spec 记录的 11 多 1 条，来自 v2 修复提交的文案更新）。附录 A 脚本会把 `docs/v3/specs/m63`、`m76`、`specs/todo/m97` 里三处行内代码教学示例（`` `](…)` ``、`` `](url)` ``、`` `](地址)` ``）误判为断链，因此给脚本加了跳过行内代码的处理，并给 `INLINE_CODE` 正则加了捕获组。

### 8.174 手机端发送按钮首次轻点被吞（维护性补丁，2026-11-06）

- 现象：手机上在指挥台或工单的输入栏敲完消息，轻点一次「发送」不发出，要再点一次才真的发出去；桌面端同一路径一次点击就发出。
- 根因：手机输入栏 `docked` 时 `fixed` 贴底。轻点「发送」会让 textarea 先失焦、键盘收起，浏览器随后才合成 `click`；这次合成 click 可能因为贴底输入栏随键盘/视口变化位移而不再派发到按钮，也可能被 iOS Safari 直接用于「第一次轻点收键盘」，两种情况下 `form` 的 `onSubmit` 都没有执行。touch 事件在一次触摸序列里始终派发给 `touchstart` 的目标，`touchend` 一定到达按钮，不受输入栏位移影响，所以在 `touchend` 发送能同时覆盖两种机制。不是请求防抖/去重（发送路径没有去重，接口无幂等键），也不是 `pending`/`disabled` 状态机（复现用例里草稿非空、按钮可用、一次 POST 都没有）。桌面 `docked=false` 且没有键盘位移，`click` 稳定命中，所以只有手机端出现。具体真机时序没有日志取证，待用户复测确认。
- 实际：`features/agent/Composer.tsx` 的发送按钮加 `onTouchEnd`：触屏上轻点结束时直接 `onSend()`，并 `preventDefault()` 拦掉随后的合成 `click`，同一次轻点只发一条；鼠标点击仍走原来的 `submit`/`click`，桌面 Enter 仍走 `onKeyDown` 直达 `onSend`。只动发送按钮，不改输入框、去重/防抖、状态机、其他贴底栏（「停止本轮」、API 调试台发送栏）与后端。
- 验证：`ConsolePage.test.tsx` 新增「手机端轻点发送按钮一次就发出，不依赖可能被键盘收起吞掉的合成 click」（输入框先聚焦，只派发 `touchstart`/`touchend`、中间失焦、不发 `click`，并断言 touch 后补发 click 仍只有一条）；把 `Composer.tsx` 还原到 `HEAD` 时用例变红（`Expected 1` / `Received 0`，已实测），修复后 114 文件 / 994 条测试全绿，`pnpm build` 与 `frontend_smoke.py` 均通过；独立复审（fresh context）结论 Approved。
- 未覆盖：真机复测（iPhone Safari / Android Chrome 键盘弹出时轻点发送、拼音未上屏时点发送、键盘弹出时点「停止本轮」）需要用户执行；jsdom 没有真实虚拟键盘与 click 抑制，只能模拟「touch 事件到达、合成 click 缺失」的时序。台账见 `docs/v3/ledgers/mobile-send-tap.md`。

### 8.177 提问不再过期与工单卡选项优先（维护性补丁，2026-11-09）

### 8.185 指挥台二次进入整页滚出视口（维护性补丁，2026-11-10）

- 现象：桌面端（≥1024px）先进「指挥台」（`/`）正常，点「工单」等其他页面正常，再点回「指挥台」后内容区一片空白：左侧导航与底部「实时连接正常」都在，`<main>` 区域只剩主题背景色；无 console 报错，刷新或向上滚立即恢复。用户 2026-11-10 截图报告。
- 根因（两层）：① 触发层：`ConsolePage`/`TicketDetailPage` 的桌面滚动容器存在 `useState` 里、由 `ref` 回调赋值，**重新挂载的首次提交里 `container` 仍是 null**；`useConversationScroll` 的 `resolveScroller` 此时回退到 `document.scrollingElement`，尾随内容变化的 layout effect 把整个 window 滚到 `scrollHeight`。二次进入时 TanStack Query 缓存已热，143 条历史在首帧渲染，文档已被撑到 16864px（body 仅 1009px），window 被滚到 15855px，985px 高的 Page 整体移出视口；滚动监听在容器就绪后只监听内层容器，没有代码把 window 滚回去（路由层也没有 `ScrollRestoration`）。② 使能层：消息里的 `.sr-only` 标签是 `position:absolute` 且没有定位祖先，包含块是初始包含块，**逃逸了会话容器的 `overflow-y-auto` 裁剪**，把根文档的可滚高度按会话全高撑高；冷加载时同样存在这段 17k 的幽灵可滚空白区（向下滚能滚进空白）。
- 只读排查证据（修复前，运行中的 production 构建）：headless Chrome 1905×1009 复现 3/3 轮；空白时 `window.scrollY=15855`、`documentElement.scrollHeight=16864`、`main` 顶部 -15855、可见区正文 0 字，但 `main.innerHTML` 344KB、`innerText` 18529 字仍在 DOM，console/异常/非 2xx 均为 0；`window.scrollTo(0,0)` 后恢复正常；拦截 `document.scrollingElement.scrollTop` 写入后同一路径不再白屏；`span.sr-only{display:none}` 或给内容容器加 `relative` 后文档高度 16864→1009。生产 bundle 与源码一致（18 个 sourcemap 的 `sourcesContent` 对 339 个源文件 0 diff），异常栈反解到 `use-conversation-scroll.ts` 的 `scroller.scrollTop = scroller.scrollHeight`。
- 实际：`useConversationScroll` 新增必填 `target: 'container' | 'document'`：桌面传 `container`，容器未就绪时 `resolveScroller` 返回 null，这一帧不滚、**不再回退整页**；手机仍传 `document`，跟随整页滚动（行为不变）。scroll 监听、`headKey` 锚点、`tailKey` 贴底、`ResizeObserver`、`scrollToBottom`、`rememberPositionBeforePrepend` 全部走同一解析，容器未就绪时一律不动窗口。`ConsolePage`/`TicketDetailPage` 的内容容器加 `relative`，把 `.sr-only` 的包含块收回滚动容器内，根文档不再被撑高。无后端、端点、wire、错误码、配置与表改动；「桌面滚容器 / 手机滚整页 / 在底部时跟随 / 上滑不拉回」的行为契约不变。
