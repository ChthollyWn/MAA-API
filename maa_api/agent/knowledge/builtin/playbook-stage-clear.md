## 原则
让内核去打，agent 只负责找方案或写方案。MaaCore 没有滑动与独立 OCR 能力，原子操作打不了关卡；历史截图不保留图像，逐格点击意味着每一步都要重新截图、重新认，又慢又容易断。顺序固定：先搜现成作业，搜不到再自己写一份，最后才考虑原子操作。

## 1. 动手前先看现状
- get_system_status / get_queue：有流水线在跑就不要抢，先说清在跑什么，再用 ask_user 发卡问是等它结束还是稍后再来。设备没连接就说明情况，征得同意后 reconnect_device。
- resolve_stage 确认关卡代号能对上；用户给的名字有歧义（例如只说「1-7 突袭」）就问清难度，不要猜。

## 2. 先搜现成作业
- search_copilots(stage=<关卡>, limit=5, only_feasible=true)：按关卡搜作业站并用账号现有干员筛。
- 本机关卡索引认不出新关卡（新活动的 EX 关等）时，不要绕路：用 search_prts 查到「关卡id」（形如 act52side_ex08），直接传给 search_copilots 的 stage；作业站按 stageId 存作业。搜索这一步不需要更新资源；但执行前要确认内核资源认识该关卡（见 §4）。
- 看每条的可行性档：
  - ok：直接用。
  - missing_one：缺一名、可借助战。先问用户同不同意借助战（借了就不用自己有这名干员），再继续。
  - infeasible：缺口名单列了缺谁、缺多少练度，如实告诉用户，别硬跑。
- 选中后用 save_copilot_draft(site_id=<作业站编号>, note=<出处与思路>) 存成本地资源。保存只做校验、不执行，也不占设备。
- 保存会跑静态检查：坐标在地图内且落在可部署格、近战远程与地块匹配、干员在账号里或是唯一允许的助战补位、部署数不超过关卡上限、技能序号不超过技能数。失败抛 COPILOT_JSON_INVALID 并逐条给 violations。照 violations 改，不要原样重试。

## 3. 搜不到就自己写一份
- 先用 get_stage_level_data 拿这关的地图、出怪与部署上限，别凭记忆画格子。
- 用 save_copilot_draft(content=<作业 JSON>, note=<思路>) 保存。作业 JSON 是 MAA 的自动战斗协议：部署序列 + 技能时机，字段与候选取值以 list_task_types 里 Copilot 的 schema 为准。
- 静态检查只管部署项。Click / Swipe 这两类动作不校验，风险留给运行时；写这类动作前先用 get_screenshot 确认当前画面与坐标系。
- 截图给模型看的副本带像素坐标网格：格宽是图宽的 1/10，每个标签就是原图像素坐标，click 直接按网格读数。click 返回前会自动等 350ms 让画面稳定；点完再截图确认，不要连续盲点。
- 写不出可行方案（缺干员、缺练度、卡在某个节点）就直说卡在哪，并给出还差什么，不要为了交差塞一份跑不通的作业。

## 4. 执行
- 执行前的位置有硬要求：游戏要停在**这关自己的「开始行动」界面**。不是首页，也不是终端页——用户 2026-10-14 纠正过两次（「任务应该是要停留在关卡页才能执行作业，不是首页」「重试」）。终端的「前往上一次作战」是回到该关的快捷入口，从那里进关卡页，截图确认画面是「开始行动」再提交。
- 作业执行需要内核资源认识这一关：Copilot 任务会读作业 JSON 里的 stage_name，在内核资源里查不到时直接报 `Not support stage`、整个任务被拒绝（2026-10-17 实机实测；本机 resolve_stage / get_stage 查不到新关卡通常意味着内核也不认识）。这时先 get_versions 看资源版本，再用 ask_user 问用户要不要更新活动资源（update_resource），更新是异步的、用 wait_update 等它结束后重跑；不要不更新就硬跑。执行位置仍要求画面停在这关的「开始行动」页，两者缺一不可。
- 先 stop_pipeline 停掉在跑的流水线，再截图确认位置：run_copilot_attempt 从「开始行动」开始打。有流水线在跑时不要提交，设备和内核的控制权只能有一个主人。
- run_copilot_attempt(copilot_id=<草稿 id>, support=<是否借助战>) 需要授权，没授权先申请 grant_copilot_attempts；被拒绝就说明情况并问用户下一步，不要重试同一张卡。
- 返回 not_started 表示战斗没开始（不在开始行动界面、编队失败或干员缺失），这一次不计次：把游戏停对位置、截图确认后再试。别在同一位置原样重试。
- 结果里 outcome 由内核判定：M57 起 `three_star` / `two_star` / `clear` / `failed` / `not_started` 会直接返回（突袭三星是 `Adverse` 标记，同样算 `three_star`），此时不需要再截图复核、也不用调 record_copilot_result。只有 outcome=unknown 才表示内核没认出来：返回里带 action_count 与动作摘要、并附了结算截图（模型可见），用 record_copilot_result 补判并如实标明是模型判定。**只有 unknown 这一步不能省**。
- **提交了就等它跑完**：run_copilot_attempt 会阻塞到结算（上限由 agent.copilot_attempt_timeout_minutes 决定）。这一轮如果被用户中断，作业流水线已经在跑，而结果不会被记录——先 get_pipeline 看那条流水线的落定情况，再决定是补 record_copilot_result 还是重新发起一次尝试；不要在中断之后直接改去点屏幕。

## 5. 失败之后
- 读动作日志摘要判断是「练度不够」还是「时机不对」，再决定改哪一步；不要放弃作业改去点屏幕，也不要原样重复同一份。
- 同一关的尝试次数由授权决定；COPILOT_GRANT_EXHAUSTED 就是用完了，停下并告诉用户。换了关卡要重新申请授权（COPILOT_GRANT_STAGE_MISMATCH）。
- 收尾按用户要求汇总：每份作业试了几次、结果是什么、判定方是谁、最后用的哪一份。

## 6. 突袭（磨难）与理智药
- 解锁：普通难度三星通关后，关卡页左下的「突袭模式」按钮才从锁定变可用。先打普通、再切突袭，顺序不能反。
- 消耗：突袭的理智消耗与普通相同（不是双倍）；首次通关给至纯源石。理智不够时点「开始突袭」会弹「使用药剂恢复理智」对话框，优先选剩余天数最少的理智药，确认后理智补上去再开打。
- 结算：普通三星是蓝星模板；突袭三星是 `StageDrops-Stars-Adverse` 模板（内核识别里同样算 `three_star`）。不要靠地图上节点的颜色猜通关状态，以 run_copilot_attempt 返回的 outcome 为准。

## 7. 2026-10-14 实战复盘（YW-1 互助会，作业站 #106030）
这一轮跑了两小时没收敛，值得记下来的点：
- 作业真的跑起来过：动作日志是「二倍速 → 部署 煌 → 摆完挂机」，3 个动作、打完退出；卡点不在作业质量，而在**没记录结果**（全程 record_copilot_result 零调用）。
- 位置错误反复出现：先停在首页提交、被内核拒或空跑；挪到关卡页才真正开打。位置确认这一步不要省，也不要靠记忆推断。
- 内核拒任务的 hint 已经写了正确做法（「先补一条 StartUp（start_game_enabled: true）再重跑，不要原样重试」），要照它做，别自己猜。
- 一次点击类操作收到 CONFIRMATION_EXPIRED：确认过期后停手、说明情况、问用户下一步，不要重发同一张确认卡。
- 全程 get_screenshot 18 次、get_logs 17 次：排查是必要的，但**日志一次只查够判断的量**（默认每条 200 字 + 关键字段，翻页用 next_cursor），别把几万字一次性拉进来。

## 原子操作的位置
它只用于单步、幂等、能截图核对的界面动作：确认编队、关掉弹窗、回到主界面。做之前先停掉流水线（避免和内核抢控制权）并截图确认，做完再截图核对。
