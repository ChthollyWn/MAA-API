title: 养成规划（精二与专精）
when_to_use: 用户说想把某干员精一/精二/专精，或问「练他需要什么材料、去哪刷、能不能帮我刷」时
---
## 前置判断
- 有流水线在跑、设备未连接、不支持视觉输入时按同一套处理：先说明在跑什么再用 ask_user 发卡问是等它结束还是稍后；征得同意后 reconnect_device；读不了画面上的材料清单就让用户直接报缺什么材料，或建议换用支持视觉的模型。

## 第 1 步：问清目标，别急着动手
必须确认三件事：干员名、目标阶段（精一 / 精二 / 专一~专三 / 模组等级）、当前状态（现在几级、精几、技能几级）。
- 精二的前置是精一满级；专精的前置是精英阶段 2。
- 用户说不清当前状态时，让他按 screen-operator 打开干员详情页，用 get_screenshot 读画面（干员详情页有等级、精英阶段、潜能、技能、天赋、信赖等信息），不要凭猜。
- 干员名先和用户对齐（俗称、别名多，模糊时追问）。
- 账号数据里练度列可能是 `null`，那是**未识别**，别说成「技能没升过」「没有专精」，也不要照 `null` 下结论。要补齐这些维度，先看 `get_skland_status`，没绑定就让用户在【更多 → 账号数据】页扫码绑定，再 `sync_skland_training` 同步一次再算；也可以按 `screen-operator` 读画面确认。
- 要一次补齐多个干员的技能等级、专精与模组，用 `sync_skland_training` 从森空岛同步：它一次性拉回**全部**干员的六项练度与信赖并写进账号表，几秒跑完、不占设备，是账号干员数据的唯一来源；账号里练度大面积未识别时先提议同步一次。它会覆盖整表练度，所以要用户确认；如果 `get_skland_status` 显示还没绑定（`bound=false`），先请用户到【更多 → 账号数据】页用森空岛 App 扫码绑定，不要自己编造练度。

## 第 2 步：用工具算出所需材料
**本服务有查干员升阶材料的工具，不要再说「没有这个工具」、也不要让用户自己报清单**：
1. `get_operator("<干员名>", sections=["costs", "potentials"])`：`costs` 给出该干员精英化各阶段的材料与龙门币清单，`potentials` 给出潜能各等级效果（潜能不涉及材料，但用户常一起问）。
2. `plan_upgrade`：把「目标干员 + 目标阶段 + 当前练度」交给它，返回一份养成规划建议（只计算、不提交任务），包含要准备哪些材料与目标关卡。返回里的 `unknowns` 列出「哪个干员的哪个练度维度未识别」，这些维度**不会**被算成增量（也不会按默认值兜底）——先按第 1 步同步一次，或把缺口原样告诉用户，不要自己替他假定。缺的是技能等级、专精或模组时，跑一次森空岛同步（`sync_skland_training`）比让用户一项项报快得多。
3. `get_depot`：核对仓库现有材料，算出「还缺多少」，别把已经够的材料算进刷图计划。
需要提醒的类别（各阶段具体数值以上面两次调用的返回为准，不要背表）：龙门币、芯片/芯片组/双芯片、精英材料、技能与专精用的技巧概要、模组数据块与干员专属材料。双芯片要在基建制造站合成，芯片助剂用采购凭证/高级凭证在采购中心换。

## 第 3 步：说清去哪刷，优先用真实数据
- 先 `get_operator(..., sections=["costs"])` + `plan_upgrade` 拿到材料清单与目标关卡，再逐项定图，不要凭记忆报「某材料最优图」。
- 某材料具体刷哪张图：`get_drop_rates(item="<材料名>")` 给按 `rate` 排序的关卡列表（行里有 `ap_cost` 与 `sanity_per_item`，可直接比性价比）；它默认只看当前开放的关卡，查已关闭的活动图要传 `include_closed=True`。
- 本账号实际记录：`get_drop_stats`（`stage="<关卡代号>"`）只看本服务打过的次数与掉落数量；`runs` 为 0 就说明本机没刷过这关，**不要拿它当掉率**，改用 `get_drop_rates` 或让用户给数据。
- 龙门币、经验（作战记录）、技巧概要、采购凭证（换芯片助剂与模组数据块）、芯片等分别在哪张图刷、今天开不开放：`get_prts_page(title="关卡一览/资源收集")` 会列出每张图的开放星期与固有掉落，用它现查，不要硬编开放日。
- 关卡代号先用 resolve_stage 确认（支持 code 与 stageId 互查），再进 drop 查询。
- 版本会调整关卡与开放日，不确定时以游戏内当日开放为准。

## 第 4 步：帮他把材料刷出来
- 提交流水线：submit_pipeline，任务数组通常是 [{"name": "StartUp", "start_game_enabled": true}, {"name": "Fight", "stage": "<关卡>", "series": 0}]。
- `stage` 支持主线关卡、资源关、剿灭写作 `Annihilation`、活动关要写完整编号；想在标准/磨难之间切换时在关卡名后加 `Normal`/`Hard`（如 `CE-6Hard`）。`stage` 不能在一个运行中的流水线里改。
- 控制次数与消耗：`times` 限制战斗次数；`series` 是连战次数（`0` = 自动取当前理智可用的最大次数，`-1` = 禁用连战）；要吃药或碎石时填 `medicine` / `stone`，这两个会触发人工确认，必须先向用户说清会消耗什么、得到确认再提交。`expiring_medicine` 已弃用，不要填。
- 提交后用 wait_pipeline 等结束；失败或被取消时说明原因并停下，不要改用原子点击硬闯。要看进度可以 get_queue 或 get_pipeline。
- 不确定任务类型或参数时用 list_task_types 查，本服务的任务类型只有 StartUp、CloseDown、Fight、Recruit、Infrast、Mall、Award、Roguelike、Reclamation、Copilot（外加自定义任务），不要编不存在的任务名。

## 第 5 步：收尾提醒
- 龙门币与芯片本都要按开放日排期，一次别只盯一个材料；缺理智时如实报需要的理智量（`get_stage` 的 `sanity` × 次数），自然恢复速度见 `get_prts_page(title="理智")`。
- 提醒精二之后等级回到 1 级（正常）、精二后还要花大量经验与龙门币才能拉满，性价比不一定高。
- 专精和模组要占基建训练室、要等真实时间，别指望一次刷完。
- 汇报时写清：目标阶段、缺什么材料、建议刷哪关（含今天是否开放）、预计理智、需要用户确认的消耗项。
