title: 查掉落与选图
when_to_use: 用户问某个材料去哪刷、某关卡掉什么，或要比较两张图的掉落收益时
---
## 回答「这关掉什么」
1. resolve_stage 确认关卡代号（code / stageId），不要直接拿用户的口语名去查。
2. get_drop_stats 传 `stage="<关卡代号>"`，看返回的 `runs`（本服务实际打过的次数）与 `items`。
3. `items` 里 `quantity` 是主掉落累计数量，`add_quantity` 是「额外物资」那一份的累计数量（日志里显示为 `数量(+额外)`）。
4. 只报「样本量 runs + 观测到的材料与数量 + 时间范围」，不要说成掉率。

## 回答「某个材料去哪刷」
1. 先确认材料名；用户用俗称时对照 glossary，或直接问清楚是哪个材料。
2. get_drop_stats 可以不传 `stage`，会聚合本服务刷过的所有关卡（可用 `since` / `until` 收窄时间范围，时间按 UTC）。从中挑出刷到过该材料的关卡，再逐关看 `runs` 与数量。
3. 比较时折算到「每点理智」而不是「每次掉落」，方法见 drop-efficiency。
4. 想看官方之外的广泛统计，让用户去游戏内的关卡详情，或 PRTS 的材料页/关卡页——那里的掉落表由企鹅物流数据统计提供，页面会标注统计区间并提示数据可能过期。

## 没有数据时怎么如实说
- `runs` 为 0、`items` 为空，只能说明「本服务还没有这些关卡的掉落记录」，绝不等于掉率为 0。
- 此时给出可选路径：①在游戏内看关卡详情；②去 PRTS 的材料页看第三方统计；③先提交一次小样本 Fight（例如 `times` 3~5），跑完再回来看数据。
- 不要凭记忆报掉率，也不要凭空给出「某材料的最优图」；没有数据支撑时请用户以游戏内或 PRTS 为准。

## 别做的事
- 不要把「固定掉落 / 小概率 / 概率 / 大概率 / 罕见」当成百分比——它们只是掉率档位，换成百分比需要第三方统计数据。
- 不要用一次作战的结果推断掉率，也不要把单次掉落量当成效率结论。
- 不要编造工具：查关卡用 resolve_stage，查掉落用 get_drop_stats；本服务没有掉率计算器，也没有查 PRTS 的工具。
- 需要看画面时用 get_screenshot（先 back_to_home 回首页更稳），这一步与掉落数据无关，别用截图去「读掉率」。
