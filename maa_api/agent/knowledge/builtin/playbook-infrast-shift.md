基建机制细节见 infrast-mechanics，界面位置见 screen-infrast。

## 什么时候该换班
- **有干员心情为 0（注意力涣散）：必须处理**。这类干员留在岗位上技能与基础效率加成全部失效，等于白占位。
- 制造站/贸易站的干员信息里有「进入注意力涣散状态的理论所需时间」倒计时，倒计时已经不长（按用户作息估个几小时）时就该安排换班。
- 办公室的联络次数达到上限后，进驻干员会暂停工作、不再消耗心情，这时不用急着换（会客室不是这样：满 10 份仍能继续搜集，收完第 11 份才停止工作并滞留线索）。
- 干员心情满了还占着宿舍位，可以换出来把位置让给心情低的干员。
- 用户如果只是问「该不该换」，先给结论和依据（谁心情见底、哪些设施效率掉了），不要直接提交任务。

## 用哪个模式
Infrast 的 `mode`：
- `0` 默认换班（单设施最优解），日常首选。内核会按自己的算法重排设施内的干员，**可能和用户手动排的班不一样**，提交前说清会动哪些设施。
- `10000` 自定义换班（读取用户配置），需要配 `filename` + `plan_index`。
- `20000` 一键轮换：会跳过控制中枢、发电站、宿舍以及办公室，其余设施不进行换班但保留基本操作（如使用无人机、会客室逻辑）。

## 关键参数
- `facility` 要换班的设施（有序，顺序就是换班顺序），默认七个全换：Mfg 制造站、Trade 贸易站、Power 发电站、Control 控制中枢、Reception 会客室、Office 办公室、Dorm 宿舍。只想动贸易站和制造站就只留这两个。该字段不支持运行中修改。
- `threshold` 工作心情阈值，取值 0~1，内核默认 0.3；越接近 0 越晚换班、越接近 1 越早换班（方向性结论，具体判定以内核为准）。
- `drones` 无人机用途，默认不使用；**mode=10000 时该字段会被忽略**。用了会消耗基建无人机（满上限的充能本来也会被丢弃，但别默认替用户决定）。
- `replenish` 贸易站「源石碎片」是否自动补货；`dorm_notstationed_enabled` 宿舍「未进驻」选项；`dorm_trust_enabled` 把宿舍剩余位置填给信赖未满干员。都默认 False，按用户要求开。
- `filename` / `plan_index` 只在 mode=10000 时生效且必填，且不支持运行中修改。

## 自定义排班方案
1. 用 `set_infrast_plan` 保存或覆盖同名方案。它是高风险工具，**一定会弹人工确认**，先把「要写入什么方案、会覆盖同名方案」讲清楚。
2. `content` 必须包含非空 `plans` 数组；顶层只允许 author、description、id、title、planTimes、plans、scheduleType、buildingType；每个 plans 项只允许 name（必填、非空字符串）、description、description_post、Fiammetta、drones、rooms、period。字段不符合校验会直接被拒。
3. 成功后记下返回的 `filename`，把它原样填进 Infrast 的 `filename`，用 `plan_index`（从 0 开始）选具体方案。
4. 本服务的工具里**没有读取或列出基建方案的工具**，写进去之后只能靠返回值确认；要核对内容就让用户在界面上看。
5. 用户从别处拿到的方案 JSON（MAA 社区方案等），先 set_infrast_plan 存一遍再引用；不要手改文件名或路径。

## 提交与核对
1. 状态摘要显示已有流水线在跑：不要打断，也不要并发提交；用 ask_user 发卡问用户是等它跑完还是稍后再来。
2. 设备未连接就说明情况并征得同意后 reconnect_device；当前模型不支持视觉输入时说明看不到心情与进驻情况。
3. submit_pipeline 提交 `[{"name": "Infrast", "mode": 0, "facility": [...], ...}]`；Infrast 没有消耗类参数，不会因为消耗品触发确认，但 set_infrast_plan 会。
4. wait_pipeline 等终态，不要反复 get_pipeline。
5. 失败或被取消就说明原因并停下，不要改用 click 手点设施；用户坚持时才用原子操作，第一次点击会弹会话授权。
6. 核对：get_screenshot 看基建总览与相关设施详情，确认还进驻着谁、有没有干员仍是注意力涣散；把「动了哪些设施、谁换下来了、还剩哪些涣散干员」写进回复。
7. **不要承诺换完立刻回满心情**：按宿舍公式估算，Lv.1 宿舍满氛围约 2.0 点/时（从 0 回满约 12 小时），Lv.5 满氛围约 4.0 点/时（约 6 小时）。
8. 结束时调用 back_to_home（安全操作，不需要确认）。
